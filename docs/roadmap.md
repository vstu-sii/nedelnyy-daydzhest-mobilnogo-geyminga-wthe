# 1. MVP-скоуп (из use cases)

MVP закрывает **UC1 + UC2 в обоих режимах - weekly и monthly**, потому что ежемесячная оценка топов адресует отдельную боль №3, а не является "довеском" к недельному выпуску. North Star и guardrails считаются **раздельно по типам дайджеста**, иначе ежемесячный риск (история, контекст) размоется в общей метрике.

**Возможности MVP:**

1. **Запуск сборки по расписанию с явным типом `weekly` / `monthly`** (оба типа).
   Критерий готовности: тип дайджеста задаётся на старте и виден аналитику в шапке.

2. **Сбор данных из 1-2 источников** (приоритетный + резервный). (оба типа)
   Критерий готовности: gross/installs/динамика подтягиваются без ручного ввода.

3. **Отбор игр за неделю: топ-3 чартов + доп. критерии.** (weekly)
   Критерий готовности: правила зафиксированы, есть лог срабатывания.

4. **Отбор проектов из топов + подъём истории за месяц.** (monthly)
   Критерий готовности: история проекта доступна в карточке без ручного перечитывания старых выпусков.

5. **Расчёт динамики gross/installs: за неделю / за месяц + тренд по неделям.** (оба типа)
   Критерий готовности: weekly - недельный срез, monthly - месячный + тренд.

6. **Гео-разбивка установок.** (оба типа)
   Критерий готовности: отображается в карточке, сверяется с источником.

7. **LLM-генерация описания идеи игры.** (оба типа)
   Критерий готовности: без галлюцинаций на тестовом наборе.

8. **Присвоение черновой категории (зелёный / жёлтый / красный) по метрикам.** (оба типа)
   Критерий готовности: помечена как "черновик", обязательна валидация.

9. **Бирюзовая категория - вручную аналитиком.** (оба типа)
   Критерий готовности: аналитик ставит флаг вручную.

10. **Сборка карточки в едином формате (3 блока).** (оба типа)
    Критерий готовности: рендер "квадратика" соответствует шаблону.

11. **Сборка "белой доски" - из недельных карточек / из месячных карточек с историей.** (оба типа)
    Критерий готовности: доска собирается без ручного вмешательства.

12. **Черновик дайджеста с указанием типа - доступен аналитику.** (оба типа)
    Критерий готовности: открывается по ссылке, все блоки заполнены.

13. **UI ревью: просмотр, правка категории/описания, публикация.** (оба типа)
    Критерий готовности: изменения сохраняются, публикация в один клик.

14. **Базовая дистрибуция (ссылка + экспорт в Slack/PDF/email).** (оба типа)
    Критерий готовности: команда получает финальный дайджест.

15. **Трекинг North Star с разбивкой по типу (weekly / monthly).** (оба типа)
    Критерий готовности: считается автоматически по каждому выпуску.

16. **Guardrail качества: % совпадения с эталонным дайджестом.** (оба типа)
    Критерий готовности: baseline зафиксирован отдельно для weekly и monthly.

17. **Guardrail задержки.** (оба типа)
    Критерий готовности: порог X соблюдается для обоих типов.

18. **Guardrail цены.** (оба типа)
    Критерий готовности: стоимость генерации <= Y% стоимости часа аналитика.

19. **Обновление истории проекта после monthly-выпуска для будущих дайджестов.** (monthly)
    Критерий готовности: история сохраняется, доступна в следующих выпусках.

# 2. Не-скоуп (явно)

Полная автоматизация без аналитика. Система не публикует дайджест сама и не присваивает финальные категории - только черновик, финальное слово всегда за аналитиком.

Отдельный формат для ежемесячного дайджеста. Никаких других представлений (таблиц, отчётов, side-by-side) - только единая "белая доска" из карточек для обоих типов.

Полное покрытие всех источников. В MVP - 1-2 приоритетных источника; расширение на остальные и сверка между ними.

Обучение своих моделей. Никаких собственных классификаторов на исторических данных, online-learning на правках аналитика или мониторинга аномалий - только базовые правила и LLM-суммаризация.

Реал-тайм и ad-hoc генерация. Только по расписанию (weekly + monthly). Запуск "прямо сейчас" вне расписания.

Интеграции и платформа. Без внешних интеграций, без мобильного приложения, без мультиязычности, без кастомизации шаблонов - базовая дистрибуция ссылкой/экспортом.

Роли и права доступа. В MVP - один уровень доступа для аналитика; разграничение ролей (аналитик / геймдизайнер / админ) - Post-MVP.

Обратная связь и персонализация. Без реакций и комментариев от команды, без подстройки дайджеста под роль читателя.

# 3. Вехи до Demo Day

Ориентир - **~12 недель** до Demo Day. Monthly-ветка стартует после того, как weekly стабильно работает end-to-end - так мы не блокируем основной сценарий на рисках истории.

**M0. Discovery & freeze** - неделя 1-2.
Что сделано: финализированы критерии отбора (weekly / monthly), правила категорий, шаблон карточки, эталонные дайджесты обоих типов.
Критерий прохождения: скоуп MVP и не-скоуп подписаны Product/VO; зафиксированы отдельные эталоны weekly и monthly.

**M1. Data pipeline v1 (weekly)** - неделя 3-4.
Что сделано: пайплайн тянет gross/installs/динамику/гео из приоритетного источника, запускается по расписанию в режиме `weekly`.
Критерий прохождения: данные по 10-15 играм собираются без ручного ввода.

**M2. Card generation + LLM description (weekly)** - неделя 5-6.
Что сделано: генерация описания идеи игры + сборка карточки в 3 блока + рендер "квадратика".
Критерий прохождения: карточки собираются end-to-end, описание не галлюцинирует на тестовом наборе.

**M3. Category draft + weekly board** - неделя 7.
Что сделано: черновая категория (зелёный/жёлтый/красный), ручной флаг бирюзового, сборка недельной доски.
Критерий прохождения: weekly-доска отрисована из автоматически собранных карточек.

**M4. Review UI + publish + North Star (weekly)** - неделя 8.
Что сделано: UI ревью, ручная правка, публикация, счётчик изменённых карточек с типом `weekly`.
Критерий прохождения: первый weekly-черновик опубликован, North Star считается.

**M5. Monthly branch: отбор + история + тренд** - неделя 9.
Что сделано: ветка `monthly`: отбор проектов из топов, подъём истории за месяц, тренд по неделям, обновление истории проекта после выпуска.
Критерий прохождения: monthly-дайджест собирается end-to-end, история проекта доступна в карточке.

**M6. Guardrails validation (оба типа)** - неделя 10.
Что сделано: сверка с эталоном (quality match), замер задержки и цены - раздельно для weekly и monthly.
Критерий прохождения: baseline-значения guardrails зафиксированы по каждому типу.

**M7. Closed beta с аналитиком** - неделя 11.
Что сделано: 1-2 реальных weekly-выпуска и 1 monthly-выпуск у пилотного аналитика.
Критерий прохождения: North Star и guardrails измерены на реальных данных, собрана обратная связь.

**M8. Demo Day prep & demo** - неделя 12.
Что сделано: полировка демо-сценария (weekly + monthly), стабилизация пайплайна, презентация.
Критерий прохождения: демо проходит end-to-end без ручных "костылей" вживую.
