## О датасете и статусе прогона

Спайки проведены на **синтетическом датасете**: игры, метрики и эталонные описания сгенерированы командой. Это позволяет контролировать свойства примеров (реальный рост vs случайный всплеск).

Прогон выполнен через OpenRouter с бесплатным роутером `openrouter/free` (автоматический выбор доступной бесплатной модели).

**Ограничение:** бесплатные модели через роутер нестабильны — часть запросов вернула пустой ответ. Это техническое ограничение бесплатного доступа, а не свойство пайплайна. Полноценная проверка — в лабе 3 на платном API.

## Спайк 1: качество суммаризации нарратива

**Вопрос:** даёт ли LLM описание, совпадающее с ручным описанием на ≥80%?

**Метод:** 5 игр, вход — `store_text`, эталон — ручное описание, оценка — ROUGE-L F1.

**Результат:**

| Игра | ROUGE-L F1 | Latency | Статус |
|---|---|---|---|
| nr_002 | — | — | ошибка (пустой ответ) |
| tt_001 | — | — | ошибка (пустой ответ) |
| so_003 | 0.000 | 5.17 с | ответ не совпал с эталоном |
| synth_004 | 0.667 | 4.42 с | хорошее совпадение |
| synth_005 | 0.444 | 5.45 с | среднее совпадение |

**Средний ROUGE-L F1 по успешным:** 0.37. **Успешных прогонов:** 3 из 5.

**Вывод:** допущение Д1 (≥80% совпадения) **не подтверждено** на бесплатной модели. Средний ROUGE-L F1 = 0.37. При этом на двух играх результат 0.44–0.67, что говорит о **потенциале механики** — проблема в слабой модели, а не в задаче.

**Решение:** для продакшна использовать платную модель Gemini 3.1 Pro (по [model-candidates.md](../model-candidates.md)). Полноценная проверка — в лабе 3. Промпт дополнить few-shot примерами.

## Спайк 2: классификация без ложных «зелёных»

**Вопрос:** не даёт ли классификатор ложную метку «зелёный» на играх со случайным всплеском?

**Метод:** 10 примеров (5 реальный рост, 5 случайный всплеск), вход — метрики за 4 недели, оценка — accuracy и false positive rate по «зелёному».

**Результат:**

| Пример | True | Predicted | False green? | Статус |
|---|---|---|---|---|
| synth_g1 | green | «the» | нет | ответ не по формату |
| synth_g2 – synth_y5 | — | — | — | ошибка (пустой ответ) |

**Accuracy по успешным:** 1 из 1, но ответ неверный по формату. **Успешных прогонов:** 1 из 10.

**Вывод:** допущение Д2 **не проверено** — бесплатная модель через роутер нестабильна, 9 из 10 запросов вернули пустой ответ.

**Решение:** (1) усилить промпт жёстким ограничением формата; (2) использовать Cotype-Nano для продакшна; (3) повторить спайк на платном API в лабе 3.

## Итог

**Проверено:** Д1, Д2 (частично).
**Не проверено:** Д3, Д4, Д5, Д6.

**Честный результат:** оба спайка выявили, что **бесплатные модели через `openrouter/free` нестабильны**. Механика суммаризации работает (ROUGE-L до 0.67 на отдельных играх), но требует сильной модели. Классификация не проверена из-за нестабильности роутера.

**Следующий шаг:** повторить спайки на платном API (Gemini 3.1 Pro + Cotype-Nano) в лабе 3.
