 Критерии успеха: недельный дайджест мобильного гейминга
 Что за проект

Агент раз в неделю собирает новости мобильного гейминга из 10+ источников, убирает мусор и кликбейт, группирует по темам и выдаёт короткий дайджест.

Смысл этого файла — заранее договориться, что считаем успехом. Без цифр и способа проверки это не метрика, а просто пожелание.

 Метрики качества

| Критерий | Что смотрим | Цель | Как проверяем |
| Точность | Нет выдуманных событий, дат, названий игр | 0 галлюцинаций на 20 дайджестов | Даём LLM исходные статьи и готовый дайджест, просим найти то, чего в источниках нет. Считаем долю таких утверждений. |
| Полнота | Все важные события недели на месте | ≥ 90% | Вручную составляем список топ-10 событий недели и сравниваем с дайджестом. |
| Релевантность | Нет воды и неважных новостей | ≥ 85% | Берём 20 дайджестов, оцениваем каждый пункт по шкале 1–5, считаем долю пунктов с оценкой ≥ 4. |
| Тон | Кратко, по делу, без кликбейта | 4.5 / 5 | LLM ставит оценку по рубрике: 1 — сухой пресс-релиз, 3 — нейтрально, 5 — идеальный дайджест. Усредняем по 10 запускам. |

Технические метрики

| Критерий | Что смотрим | Цель | Как проверяем |

| Скорость | Время генерации одного дайджеста | < 45 сек (p95) | Таймер в коде от запроса до ответа. Считаем 95-й процентиль по 50 запускам. |
| Стоимость | Расход токенов на один дайджест | < $0.05 | Считаем input_tokens × цена + output_tokens × цена по логам API. |
| Формат | Ответ всегда валидный JSON | 100% | Валидация через Pydantic. Если ошибка — перезапуск. |
| Источники | Сколько статей обработали за раз | ≥ 10 | Счётчик в логах пайплайна. |

Связь с болями из PRD

| Боль | Как решаем | Как меряем |

| Много источников, нет времени читать | Собираем всё в один короткий файл | Время чтения < 2 мин (слов / 200) |
| Много кликбейта и мусора | Фильтр по ключевым словам + ранжирование через LLM | Релевантность ≥ 85% |
| Пропускаю важные события | Сканируем 10+ источников за неделю | Полнота ≥ 90% |

 Что меряем автоматически в лабе 3

Кодом:
- скорость
- стоимость
- валидность JSON
- количество источников

Через LLM:
- точность
- тон

Руками:
- полнота
- релевантность
