# DoD всех артефактов

DoD — это когда мы считаем артефакт готовым. Не «вроде норм», а по конкретным пунктам. Каждый пункт можно проверить: либо он есть, либо нет, либо это число, либо ссылка.

## 1. PRD

- Лежит в `docs/product/prd.md` — проверяется открытием репозитория.
- Боли сегмента описаны — минимум 3 штуки, считаем по разделу.
- Целевая аудитория указана — да или нет, смотрим раздел.
- Есть ссылка на источник болей — интервью или опрос, проверяется переходом по ссылке.

## 2. success-criteria.md

- Лежит в `docs/quality/success-criteria.md`.
- У каждой метрики есть целевое число — открываем таблицы и смотрим.
- У каждой метрики есть способ подсчёта — там же.
- Минимум 5 метрик качества и 3 инженерных — считаем строки.
- Есть связь с болями из PRD — отдельный раздел.
- Указано, что автоматизируется в лабе 3 — отдельный раздел.

## 3. golden-dataset-plan.md

- Лежит в `docs/quality/golden-dataset-plan.md`.
- Источник примеров описан — минимум 3 источника, считаем в разделе.
- Версия датасета и дата фиксации указаны.
- Владелец датасета указан.
- Есть пример записи в JSON — блок с кодом.
- Объём датасета указан — 30–50 записей.
- Есть 2–3 примера, показывающие формат — блоки с кодом.

## 4. dod.md (этот файл)

- Лежит в `docs/quality/dod.md`.
- DoD описан для каждого артефакта команды — считаем разделы.
- Каждый критерий проверяемый: да/нет, число или ссылка.
- Указано согласование с Product и командой — раздел ниже.

## 5. Pull Request

- PR создан из ветки студента в main — проверяется по ссылке.
- В PR не меньше 2 изменённых файлов — вкладка Files changed.
- У всех коммитов осмысленные сообщения — вкладка Commits.
- PR не смержен без ревью — смотрим статус.
