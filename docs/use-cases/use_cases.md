# Use Case 1: Аналитик публикует дайджест (еженедельный / ежемесячный)

Актёр: Продуктовый аналитик

Цель: Получить готовый дайджест нужного типа (еженедельный или ежемесячный) и опубликовать его для команды без ручного сбора и оформления данных

Контекст:

Наступил день публикации. Для еженедельного дайджеста - пятница/понедельник, система собрала данные по играм за неделю. Для ежемесячного - конец месяца, система подняла историю по проектам за период и пересобрала оценку топов.

Тип дайджеста определяет набор карточек: у еженедельного - игры, попавшие в отбор за неделю; у ежемесячного - проекты из топов с динамикой за месяц и историческим контекстом.

Предусловие: Система уже сгенерировала черновик дайджеста соответствующего типа.

Шаги:

Аналитик открывает сгенерированный черновик дайджеста (доску с карточками). Система показывает тип дайджеста (еженедельный / ежемесячный) в шапке.

Система показывает список карточек с заполненными блоками: шапка игры, описание, динамика метрик, присвоенный цвет категории. Для ежемесячного дайджеста дополнительно подтянута история проекта за период.

Аналитик просматривает карточки на доске.

Если карточка не вызывает вопросов - аналитик оставляет её как есть.

Если категория или данные выглядят спорно (особенно при ежемесячной оценке - «скатился» / «удержал позиции») - аналитик открывает карточку и меняет значение вручную (см. UC3).

Аналитик нажимает «Опубликовать».

Система рассылает/публикует финальный дайджест команде.

Результат: Дайджест опубликован и доступен геймдизайнерам; зафиксировано, сколько карточек было изменено вручную (для метрики North Star), с разбивкой по типу дайджеста.

Постусловие: Выпуск сохранён в архив; для ежемесячного - обновлена история проекта, доступная в следующих выпусках.

# Use Case 2: Система формирует дайджест (еженедельный / ежемесячный)

Актёр: Система (пайплайн сборки)

Цель: Автоматически собрать данные и подготовить черновик дайджеста нужного типа с карточками и предварительными категориями до того, как его увидит аналитик

Контекст: Наступило время запуска сборки:

еженедельный - раз в неделю (к пятнице/понедельнику), отбор игр по топ-3 чартов и доп. критериям за неделю;

ежемесячный - в конце месяца, отбор проектов из топов и пересборка оценки с подтягиванием истории за период.

Предусловие: Задан тип запуска (weekly / monthly) и доступны источники данных.

Шаги:

Система определяет тип дайджеста: weekly или monthly.

Система получает данные по играм/проектам из источников (SensorTower / AppMagic / Data.ai, соцсети).

Ветка weekly: система отбирает игры, удовлетворяющие критериям недели (топ-3 чартов + доп. критерии), и формирует карточки по каждой.

Ветка monthly: система поднимает историю по проектам из топов за месяц, рассчитывает динамику за период и формирует расширенные карточки с историческим контекстом.

Система рассчитывает динамику gross/installs и гео-разбивку (для monthly - за месяц, с трендом по неделям).

Система генерирует краткое описание идеи игры на основе материалов стора.

Система присваивает предварительную категорию (зелёный/жёлтый/красный/бирюзовый) на основе метрик.

Система собирает карточку в едином формате (три блока: шапка, описание, динамика).

Система добавляет карточки в черновик дайджеста соответствующего типа.

Результат: Готовый черновик дайджеста (weekly или monthly) с карточками и черновыми категориями ожидает проверки аналитиком.

Постусловие: Для monthly - обновлена история проекта, доступная в следующих выпусках.
