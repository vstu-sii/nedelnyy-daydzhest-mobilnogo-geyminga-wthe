# Документация AI-части — Lab 5

## Назначение

AI-часть формирует черновик карточки мобильной игры:

- краткое описание по исходному тексту;
- категорию динамики недельной выручки;
- метаданные генерации;
- признак обязательной ручной проверки.

Эксперимент Lab 5 охватывает суммаризацию и классификацию.
Сбор рыночных данных, поиск похожих проектов и публикация
не входят в измеренный сценарий.

## Финальный пайплайн

1. Проверка идентификатора, описания и числовых метрик.
2. Классификация тренда правилами Python.
3. Генерация описания моделью Qwen.
4. Проверка JSON, game_id и завершённости генерации.
5. Формирование карточки со статусом draft.
6. Ручная сверка содержания с источником перед публикацией.

Сборка карточки реализована в `ml/pipeline.py`.

Ошибки не подменяются успешными ответами.
Невалидное описание блокирует формирование карточки.

## Модель и среда эксперимента

- Модель: Qwen/Qwen2.5-3B-Instruct.
- Revision: aa8e72537993ba99e69dfaafa59ed015b17504d1.
- GPU: Tesla T4.
- Тип весов: float16.
- Python: 3.13.16.
- PyTorch: 2.14.1+cu130.
- Transformers: 4.48.3.

Фактически использованная среда записана в:

    docs/experiments/qwen/environment.json

Параметры генерации:

- do_sample=False;
- max_new_tokens=256;
- temperature=None;
- top_p=None;
- top_k=None;
- pad_token_id=151645.

Модель загружается один раз. Перед измерениями выполняется прогрев.
Время загрузки и прогрева не входит в latency генерации.

## Версии промптов

Файл: `ml/prompts/lab5.py`.

Классификация:

- lab3 — исходная короткая инструкция;
- lab4 — описание категорий и ограничение формата;
- final — экспериментальный кандидат с числовыми порогами.

Описания:

- lab4 — промпт предыдущей лабораторной;
- final — краткое нейтральное описание с ограничением фактов;
- without_grounding — final без ограничения фактов.

Классификационный промпт final отклонён по результатам эксперимента.
В итоговом пайплайне категория вычисляется кодом.

Для описаний выбран final. Он не гарантирует отсутствие
неподтверждённых фактов, поэтому требуется ручная проверка.

## Классификация числового тренда

Файл: `ml/classification.py`.

Вход: четыре последовательных недельных значения gross.

Требования:

- ровно четыре числа;
- значения конечные и неотрицательные;
- первое значение больше нуля;
- строки и логические значения не допускаются.

Правила:

- green: каждое значение строго больше предыдущего,
  общий рост не менее 15%;
- red: каждое значение строго меньше предыдущего,
  общее падение не менее 15%;
- yellow: остальные случаи.

Некорректный вход вызывает ValueError.

Категория turquoise не вычисляется: для неё необходимы
сведения о сходстве с собственным проектом.

## Контракт генератора описания

Пайплайн принимает функцию:

    generate_summary(game_id, store_description)

Она должна вернуть словарь:

    {
        "response": "JSON-ответ модели",
        "finish_reason": "stop"
    }

Дополнительные метаданные:

- latency_s;
- prompt_tokens;
- completion_tokens;
- model.

Содержимое response:

    {
        "game_id": "исходный идентификатор",
        "narrative": "непустое описание"
    }

Сырые ответы модели рассматриваются как недоверенные данные.

## Валидация ответа

Файл: `ml/validation.py`.

Проверяются:

- штатное завершение генерации;
- корректный JSON без markdown и пояснений;
- точный набор полей;
- совпадение game_id с исходным;
- непустой narrative;
- допустимая одиночная категория при оценке
  экспериментальных классификационных ответов.

При нарушении контракта возникает OutputValidationError.

Валидность JSON не подтверждает фактическую точность.
Автоматическая проверка русского языка и достоверности
содержания не заявляется выполненной.

## Результат пайплайна

Функция build_game_card возвращает:

- game_id;
- narrative;
- category;
- classification_method;
- review_required;
- publication_status;
- generation_metadata.

Значения по умолчанию:

    classification_method = "rules-v1"
    review_required = True
    publication_status = "draft"

Пайплайн не публикует карточку автоматически.

## Инструменты и доступ

В локальном эксперименте модель генерирует текст.
Function calling и доступ к базе данных не используются.

Модель не получает API-ключи, не выполняет команды,
не изменяет файлы и не публикует данные.

OpenRouter использовался в предварительных пробах.
Эти ответы и события HTTP 429 не входят в метрики Qwen.

## Воспроизведение

### Проверка сохранённых результатов

Из корня проекта:

    python evals/summarize_results.py

Скрипт проверяет наличие всех 72 ответов без дублей
и записывает пересчитанные метрики в:

    docs/experiments/qwen/summary.json

### Проверка кода

Из корня проекта:

    python -m unittest discover -s evals -p "test_*.py" -v

Тесты не требуют GPU, API-ключа или загрузки модели.

### Повторная генерация

Ноутбук:

    docs/experiments/lab5.ipynb

В Colab выбрать T4 GPU, загрузить указанную модель и revision,
использовать сохранённые промпты и параметры генерации.

Для нового эксперимента следует использовать отдельную папку
результатов. Нельзя смешивать ответы разных моделей,
версий промптов или параметров.

Greedy decoding снижает случайность, но побитовое совпадение
между разными GPU и версиями библиотек не гарантируется.

- Датасет мал и синтетический.
- Один прогон каждого варианта.

  по которой сформированы эталоны.

- Стоимость GPU не рассчитана.
- Нет измерений на реальном трафике.
- Полный сценарий на релизном теге требует отдельной проверки.
- Достижение North Star не подтверждается этим экспериментом.
