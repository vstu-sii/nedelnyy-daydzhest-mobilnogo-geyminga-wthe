# Отчёт по стоимости

## 1. Сокращение контекста (Промпты v2)

В лабе 3 мы использовали длинные промпты без ограничений. В лабе 4 мы переписали их (v2), добавив жесткие инструкции.
Парадоксально, но добавление правил (например, «не используй markdown») заставило модель **отвечать короче и точнее**, что резко сократило генерацию токенов.

**Цифры (из A/B теста):**
- Средние токены на v1: **3293**
- Средние токены на v2: **1867**
- **Экономия:** 43%

## 2. Кэширование повторяющихся запросов

В пайплайне дайджеста одни и те же игры могут запрашиваться несколько раз (например, при генерации черновика и финальной версии, или при ежемесячном пересмотре).

Для экономии мы внедрили **базовое кэширование** в код `ml/models/baseline.py`.
Логика: если мы уже генерировали описание для `game_id` с таким же `store_description`, мы берем его из словаря, а не идем в API.

**Стоимость сценария до/после:**
- **До:** 100% запросов идут в API.
- **После:** при повторном запуске в тот же день (например, при отладке) 100% запросов берутся из кэша. Стоимость = **$0**.
