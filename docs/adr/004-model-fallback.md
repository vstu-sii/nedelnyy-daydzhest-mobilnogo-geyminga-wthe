
# ADR-004: Резервная модель и ограничения использования LLM

## Статус

Принято. Реализация переключения ожидает подключения реального LLM-провайдера.

## Контекст

Сервис генерирует дайджесты мобильного гейминга.
При использовании языковых моделей необходимо контролировать
стоимость запросов и обеспечивать доступность сервиса.

Основные риски:
- превышение бюджета;
- недоступность основной модели;
- увеличение времени ответа;
- использование модели, не разрешённой политикой приложения.

## Решение

Предусмотреть две модели:

1. Основная модель — используется для стандартной генерации.
2. Резервная модель — более дешёвая модель, используемая
   при недоступности основной модели или превышении установленного
   порога стоимости.

Переключение должно выполняться на стороне backend.

Список разрешённых моделей хранится в коде приложения.
Неизвестные модели должны блокироваться.

## Правила переключения

Резервная модель может использоваться, если:
- основная модель возвращает ошибку доступности;
- основная модель превышает установленный таймаут;
- срабатывает правило ограничения расходов.

Переключение не должно обходить ограничения пользователя
по количеству запросов и токенов.

## Контроль расходов

Backend должен учитывать:
- количество запросов пользователя за сутки;
- оценочное количество использованных токенов;
- стоимость обращений к моделям после подключения провайдера.

При превышении лимитов событие должно записываться в журнал
и отображаться в Grafana.

## Безопасность

- Разрешённые модели определяются в backend.
- Клиент не может самостоятельно назначить произвольную модель.
- Запрещённые модели отклоняются приложением.
- Секреты провайдера хранятся в переменных окружения.

## Последствия

Преимущества:
- возможность снизить расходы;
- повышение устойчивости сервиса;
- централизованный контроль моделей.

Ограничения текущей реализации:
- используется локальная демонстрационная модель;
- реальный LLM-провайдер ещё не подключён;
- автоматическое переключение на резервную модель пока не реализовано;
- фактическая стоимость запросов пока не рассчитывается.

## План дальнейшей реализации

1. Подключить LLM-провайдера.
2. Добавить основную и резервную модели в список разрешённых.
3. Реализовать переключение при ошибках и превышении бюджета.
4. Добавить учёт фактических токенов и стоимости.
5. Настроить предупреждения о расходах.
